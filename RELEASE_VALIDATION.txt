WINDOWS BUILD PIPELINE
----------------------
The Windows scripts now provide the D2 Damage Tracker-style sequence:
Python runtime discovery/installation, isolated venv, dependency installation,
MSVC/SDK resource compiler provisioning, one-file console EXE build, CFFI DLL
build with embedded icon/version resources, pre-sign smoke tests, Authenticode
signing, SignTool/AuthentiCode verification, post-sign smoke tests, Desktop

this Linux environment. BUILD_AND_SIGN_WINDOWS.bat must be run on Windows 10/11
x64 to produce the signed Windows EXE and DLL. The source package contains the
complete build/sign tooling, not precompiled Windows PE binaries.

SIGNING TRUST
-------------
The Windows default certificate is self-signed and trusted only in the current
Windows user's trust stores. It does not provide public publisher trust or
SmartScreen reputation. Public Windows distribution requires a CA-issued
Authenticode code-signing certificate.

The Linux certificate is a self-signed development certificate. Detached
signatures prove integrity relative to the included public certificate; they
do not establish public publisher identity.

WINDOWS RC HOTFIX (3.4.1)
------------------------
The DLL VERSIONINFO template now uses self-contained numeric FILEOS and
FILETYPE constants (0x00040004L and 0x00000002L). This avoids RC2104 when
rc.exe is launched without an initialized Windows SDK include environment.
The Windows PyInstaller command explicitly includes only Plyer's Windows
notification backend instead of recursively collecting Android/iOS/macOS/
Linux backends; this removes irrelevant platform imports and the optional
Android jnius collection warning.
