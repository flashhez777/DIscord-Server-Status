DISCORD GLOBAL STATUS MONITOR 3.4.1 - BUILD INFO
=================================================

WINDOWS BUILD AND SIGN PIPELINE (ALIGNED WITH D2 DAMAGE TRACKER)
---------------------------------------------------------------
  1. Discover/reuse an x64 CPython 3.11-3.15 installation; provision only if
     no supported runtime exists. Never send manager commands to legacy py.exe.
  2. Create a private .build\windows\venv and install requirements-build.txt.
  3. Read the one canonical version from dgsm_version.py and generate both
     PyInstaller EXE metadata and Windows DLL RC metadata from templates.
  4. Build DiscordGlobalStatusMonitor.exe as a one-file console application
     with DGSM.ico and Windows version information.
  5. Compile assets\DGSM.rc using Windows SDK rc.exe and link the .res into
     the CFFI C ABI DLL with the MSVC x64 toolchain.
  6. Run EXE --help/--version and C ABI DLL smoke tests before signing.
  7. Find an installed Microsoft Authenticode-valid SignTool; if absent,
     download Microsoft.Windows.SDK.BuildTools from NuGet into a temporary
     directory, validate the embedded signtool.exe signature, and clean it up.
  8. Reuse/create a CurrentUser code-signing certificate or accept a PFX.
     Local self-signed certs are exported as .cer and trusted only for the
     current user in Root and TrustedPublisher stores.
  9. Sign the EXE and DLL using SHA-256 Authenticode. Try DigiCert and Sectigo
     RFC 3161 timestamping; if both fail, sign without timestamp and report it.
 10. Run SignTool verify and Get-AuthenticodeSignature for both files, then
     re-run native artifact smoke tests after signing.
 11. Create the Desktop shortcut, package the signed outputs, emit SHA-256
     manifests and clean temporary build files unless -KeepBuildCache is set.

UAC / USER PROFILE
------------------
Only Microsoft installers that need machine-level installation are started
with UAC. DGSM itself is not restarted as Administrator: its local signing
certificate, logs, signing report and Desktop shortcut therefore belong to
the user who launched the builder, not the elevated installer account.

SIGNING TRUST
-------------
The default self-signed certificate is for local development. It is installed
in CurrentUser\My and trusted in CurrentUser\Root and CurrentUser\TrustedPublisher.
It does not establish a public publisher identity, SmartScreen reputation or
trust on another computer. Public releases require a CA-issued code-signing
certificate. Set DGSM_PFX_PATH or pass -PfxPath to use it; the password is
prompted securely unless DGSM_PFX_PASSWORD is provided by automation.

OUTPUTS
-------
  dist\windows\exe\DiscordGlobalStatusMonitor.exe
  dist\windows\dll\discord_global_status.dll
  dist\windows\signing\signing-report.txt
  dist\windows\DiscordGlobalStatusMonitor-Windows-x64.zip
  dist\windows\DiscordGlobalStatusMonitor-Windows-x64.zip.sha256

The CFFI DLL is Python-backed and requires the same CPython minor runtime used
to build it, plus the companion dgsm_version.py, monitor source and backends.
The standalone EXE bundles its CPython runtime and Python dependencies.

PowerShell captures native stdout/stderr/exit codes using .NET ProcessStartInfo.
Timestamped logs are retained in .build\windows\logs.
